# Training data

Every recipe trains on a conversation JSONL under `data/` (`data.train_eval_path` in
`configs/llm/*.yaml`). The corpora are generated by `scripts/generate_distill_dataset.py`
from Open Perfect Blend prompts answered by a teacher served with vLLM; each data recipe in
`configs/data/` pins the teacher and prompt-set revisions.

## Published corpora

Every corpus a recipe trains on is published in the [`qatfactory` Hugging Face organization](https://huggingface.co/qatfactory).
All are public, gated datasets (accept the terms on the dataset page; access is granted automatically), so log in first
with `hf auth login`.

Each dataset also carries its provenance: `provenance.json` (generator commit, recipe, vLLM
image digests, hardware, prompt-pool and data sha256), the generator's `.meta.json` (resolved
config and merge statistics) and the generation environment's `pip freeze` under `env/`.

## Regenerating a corpus

Serve the teacher as the recipe header says (the pinned `--revision`, `--reasoning-parser`,
one data-parallel replica per GPU), then on one node:

```bash
python scripts/generate_distill_dataset.py configs/data/openperfectblend_100k_qwen3_5_9b.yaml
```

Across N nodes, build the prompt pool once, run one worker per node against that node's
server, and merge:

```bash
python scripts/generate_distill_dataset.py <recipe> --pool-only
python scripts/generate_distill_dataset.py <recipe> --output.num_workers N --output.worker_index k   # on node k
python scripts/generate_distill_dataset.py <recipe> --merge-only
```

A rerun resumes each worker from its `raw-<k>.jsonl` shard. The prompt pool is deterministic:
`<output>.shards/prompts.jsonl` should hash to the `pool_sha256` in the published
`provenance.json` (Qwen3.5-9B 100k `909f1d3a…f673`, Finding 4 `afc985ed…d036`). Sampling is
not, so a regenerated corpus has the same prompts and recipe but not byte-identical answers.

The published corpora were generated with `vllm/vllm-openai:v0.30.0` (aarch64 on 4x GB300
nodes, x86_64 on 8x H100 nodes) and `datasets` 5.1.0 for the generator. Training needs a
different `datasets`: 5.1.0 breaks `Dataset.from_dict`, which tokenization uses, so
`pyproject.toml` excludes it.
